# LazyForza 性能基线

性能门槛覆盖当前最频繁、最容易随路线规模退化的两条纯计算热路径：

- 赛道空间索引投影：3,000 点路线、50,000 次近邻投影，总耗时不超过 1,500 ms，托管分配不超过 256 B/次。
- 速度峰谷包络降采样：120,000 个采样点压缩到 1,000 点、重复 40 次，总耗时不超过 600 ms，托管分配不超过 16 KiB/次。

运行命令：

```powershell
dotnet run --project tools/LazyForza.Performance/LazyForza.Performance.csproj -c Release
```

工具会先预热 JIT，再强制回收并分别测量耗时和当前线程托管分配。任一阈值超限时退出码为 1，可用于本地开发和持续集成的性能回归门禁。阈值刻意保留不同 Windows 设备的波动空间；优化判断同时比较同一设备、同一 Release 构建的优化前后结果。

## 2026-07-29 基线与优化结果

同一台设备、.NET 9.0.18、Release 构建：

| 指标 | 优化前 | 优化后首次复测 | 最终复测 |
|---|---:|---:|---:|
| 50,000 次空间投影总耗时 | 294.046 ms | 161.425 ms | 290.695 ms |
| 空间投影托管分配 | 3,131.52 B/次 | 40.00 B/次 | 40.00 B/次 |
| 40 次速度包络总耗时 | 56.749 ms | 64.980 ms | 131.092 ms |
| 速度包络托管分配 | 8,056 B/次 | 8,056 B/次 | 8,056 B/次 |

空间投影通过复用线程内候选段缓冲，最终复测相较初始基线减少约 98.7% 托管分配。优化后的总耗时在多次复测中为 161–291 ms，最终值仍略低于初始基线；稳定收益是显著降低高频识别时的 GC 压力。速度包络算法未改动，其复测波动仍远低于门槛。

主窗口概览页的数据库计数从每 500 ms 查询一次改为最多每 2 秒查询一次，因此页面常驻时的计数查询频率由每秒 4 次降为每秒 1 次；离开再进入页面会立即失效缓存并刷新。
