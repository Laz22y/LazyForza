# LazyForza 文档

LazyForza 是面向 Forza Horizon 6 的本地遥测、驾驶分析与地产赛事工具。客户端只使用 FH6 官方 UDP Data Out，不读取游戏内存，不注入 DLL，不修改游戏进程。

- 客户端：Windows 10/11 x64
- 当前客户端：`1.5.5 · City Life`
- 当前 RaceServer：`0.6.0`
- 官网：<https://laz22y.github.io/LazyForza/>
- 客户端仓库：<https://github.com/Laz22y/LazyForza>
- 服务端仓库：<https://github.com/Laz22y/LazyForza.RaceServer>

GPT-5.6 Sol 参与了此前版本的开发。1.5.3 版本起由 GPT-6 Astra 开发。

参与开发或使用 Coding Agent 时，从仓库根目录的 [`AGENTS.md`](../AGENTS.md) 开始；它列出当前模块边界、跨仓库同步范围和验证矩阵。

## 1. 快速开始

### 1.1 下载与安装

从 [GitHub Releases](https://github.com/Laz22y/LazyForza/releases/latest) 或官网的 GitCode 下载入口获取最新版：

- 安装版：运行 `win-x64-setup.exe`，默认安装到 `C:\Program Files\LazyForza`。安装器创建开始菜单入口；桌面快捷方式和 `.lfztelemetry`、`.lfzlap`、`.lfzestate` 文件关联可在安装时选择；
- 便携版：下载 `win-x64.zip`，完整解压后运行 `LazyForza.App.exe`。便携版不写入注册表、不创建开始菜单入口，也不注册文件关联。

两种版本都包含 .NET 运行时，主程序功能与数据格式相同。

不要直接在 ZIP 压缩包内运行。更新、日志、录制和本地数据库都需要正常的可写目录。

### 1.2 首次启动

首次启动不会直接显示主窗口。初始化指引依次设置界面语言、可选玩家代号、数据目录、关闭窗口行为和 FH6 Data Out。最后一步收到有效遥测后会自动完成，也可跳过连接直接进入主窗口。跳过只省略本次连接确认，之前选择的设置仍会保存，后续启动不会重复显示指引。

直接关闭初始化窗口会退出整个程序且不写入完成标记；下次启动会重新打开初始化指引。

旧版升级后会执行一次初始化。便携版将完成状态保存在当前软件目录中：覆盖更新原目录不会重复初始化，解压到新目录则视为新的便携实例。安装版正常升级保留完成状态；卸载会重置该状态但保留数据库，重新安装后再次显示指引。语言、UI 强调色、数据目录和关闭行为可在设置页修改。强调色提供默认蓝、暗夜紫、清新绿、鲜艳红、纯粹白和低调灰六种选择，只改变界面高亮与选中状态。

### 1.3 配置 FH6 Data Out

在 FH6 的“设置 > HUD 与游戏玩法”中：

1. 开启 `Data Out`；
2. 地址填写 `127.0.0.1`；
3. 端口填写 `2299`。

返回驾驶后，LazyForza 会自动接收数据。主界面显示 Live 状态即表示连接成功。

在「设置 → 遥测与录制」可以修改监听地址与端口。端口允许 1–65535；5200–5300 会显示可能与游戏冲突的建议，可关闭并继续使用，实际端口占用仍会报错。

需要同时向其他软件或设备发送数据时，在同页开启「遥测转发」，填写接收端的 IP 与 UDP 端口。同机软件可用 `127.0.0.1`，但目标端口不能与 LazyForza 自己的监听端口相同。支持一个 IPv4／IPv6 单播目标，保持 Live 原始 324 字节不变；默认关闭，模拟与回放不会转发。接收端应支持 FH6 Data Out 格式；发送统计只表示本机已提交 UDP 包，不代表设备确认接收。

### 1.4 第一次使用建议

1. 在 HUD 设置中只开启当前需要的部件；
2. 打开布局编辑器，调整位置、缩放和透明度；
3. 正常完成几圈，让程序建立车辆与赛道记录；
4. 需要复盘时再启用自动录制，避免无目的地长期积累文件。

## 2. 客户端功能

### 2.1 实时 HUD

主仪表盘可显示速度、挡位、转速灯带、踏板、方向输入、轮胎、动力与车辆性能等级。各部件可独立开关、移动、缩放和调整透明度。窗口支持置顶和鼠标穿透，不占用游戏操作焦点。

圈速 HUD 与地产赛事 HUD 使用独立布局。布局编辑时可以暂时隐藏部件，便于处理重叠区域。

### 2.2 圈速与走线分析

LazyForza 按赛道距离对齐单圈，联动显示：

- 当前圈、个人参考圈与分段时间；
- 速度、油门、制动和方向输入；
- 走线及距离游标；
- 单圈稳定性、分段趋势和组合最佳。

紫色分段表示本地记录中同一性能等级下的最快分段。

### 2.3 车辆与换挡学习

程序按车型、性能等级和可观测调校特征保存换挡学习结果。配置匹配以这些特征为依据；FH6 UDP 未提供调校 ID。

车辆名称映射来自 [HDR 维护的 FH6 Car Ordinals 车辆标识符文档](https://gist.github.com/HDR/0659d1717bc61504bf83750628963f4f)，使用内置快照和当前数据目录下 `Cache/vehicle-names.json` 中的有效缓存，离线也可使用。每次启动检查 GitHub 上游修订；发现变化后显示来源、当前与上游修订、时间和最近提交的文本增删行数，经用户确认才下载名称数据。行数不是车辆增删数量。

选择「稍后更新」或关闭提示窗，下次启动仍会提示；选择「忽略本次更新」后，不再提示或下载该修订，后续新修订仍会提示。「设置 → 维护 → 车辆名称库」提供手动检查按钮，同样尊重已忽略的修订。下载校验成功后原子替换缓存并立即刷新名称，无需升级或重启 LazyForza；离线、取消、数据异常或下载失败时保留已有名称库，缓存缺失或损坏时使用内置快照。检查与下载不会上传车辆配置或遥测数据。

车辆配置的自动名称按车辆编号读取当前名称库，因此此前未知车辆补录名称、以及上游名称修正，都会反映在已有配置中。玩家手动命名的配置始终保留手动名称，不会被上游名称覆盖。

应用升级继续使用原数据目录中较新的有效名称库。配置备份、车辆备份和自动更新前备份均包含名称库；恢复时保留本地缓存、内置快照和备份中较新的有效版本，覆盖恢复也遵守此规则。旧备份没有名称库时保持当前名称数据。设置中更换数据目录会携带名称库，原有圈速、车辆配置等数据仍需通过备份迁移；在新预览文件夹首次初始化时也可直接选择原数据目录。

### 2.4 自动录制与回放

「记录未匹配赛道」默认关闭，开关常驻圈速分析页顶部，可通过旁边的图钉固定到侧栏。圈速分析启用且此开关开启后，未匹配官方或个人赛道库的赛事才会记录。关闭开关立即停止采集并丢弃当前未完成片段，已保存记录仍可分析；官方和个人赛道的正常计圈不受影响。在分析页选择「未命名路线」即可查看圈速、分段、速度、输入和走线；完整圈旁的「收录到个人赛道库」可将路线加入个人预设，不收录也能分析。首个完整圈确定路线与分段，后续圈沿用同一参考。收录后可在赛道库重命名，已有圈记录保持可比。

再次完成同一未收录路线时，程序按完整路线匹配并合并记录；历史重复路线也会在启动时核对归并。没有圈记录的未收录路线不显示在选择栏。比赛结束后，可直接「删除路线记录」，或选择「归入已有赛道」并查看路线对照。路线明显不匹配时可勾选「强制归入」，这类记录保留原始数据，但不计入最快圈。

中途开始、倒带、遥测缺口或提前结束的片段标为「未完成」，可查看曲线和走线，不计入最快圈，也不能用于收录。采样不足 10 秒、连续行驶不足 100 米或不足 40 个样本的短片段不保存为圈记录。未知定点路线没有完成计时信号时按未完成记录保留。记录过程中每 5 秒保存检查点，异常退出后从最近检查点恢复。导出圈速和备份圈记录时包含对应路线；带路线的圈速文件导入后默认不加入个人预设，需使用支持该格式的新版本读取。

自动录制默认关闭。启用后可保留赛前 15 秒和赛后 10 秒，并设置容量上限。默认策略是在达到上限时停止新录制，不主动删除文件；用户开启轮换后，程序仍会保护手动固定、个人最佳圈和需要诊断的样本。

回放工作台支持 `.lfztelemetry` 文件，并联动时间轴、驾驶输入、走线和动态遥测。

1.5.5「City Life」新增车辆名称库独立更新、可选的未匹配赛道记录、HUD 布局方案和连续实时 Delta，补充江户环道赛与首都冲锋赛，并改进圈记录管理与弹窗显示。 地产赛事使用 RaceServer `0.6.0` 和协议 v2。

圈速分析按比赛整理记录，进入「单圈对比」后默认显示最近有效圈。展开「选择对比圈」，勾选最多四圈后点击「查看对比」；等级筛选只列出有记录的等级。「曲线」「走线」「弯道」页签切换不同分析视图，速度与输入图表带有距离及数值刻度。删除操作统一位于「管理圈速记录」，仍需确认；导入与导出常驻页面顶部，记录管理位于性能等级筛选附近；实时分段在「当前比赛」查看。

在比赛记录中选中一圈后点击「管理圈记录」，或在单圈列表点击行尾菜单，可收藏、命名、填写备注或固定为参考。名称最多 80 字符，备注最多 2,000 字符；列表支持搜索名称、备注与车型，并可只看收藏。固定参考用于分析页面，在路线修订、方向、分段版本和车辆条件兼容时优先选中；同一条件下重新固定会替换原有参考，不改变圈时或历史最快成绩。收藏、名称、备注和固定标记随备份及圈速文件保存；旧文件没有这些标记时按普通记录读取。

「设置 → 遥测与录制 → 圈记录存储」可设置每赛道的保留目标，默认 500 圈，范围 1–10,000。自动清理保护收藏圈、固定参考圈，以及每种车型与兼容可观测车辆条件下的最快有效代表圈。车型、性能等级、PI、驱动、气缸数、转速、已记录的齿比与动力特征用于区分条件，不据此认定游戏内调校或天气相同。保护圈所在场次与最近场次完整保留，因此总圈数可以超过目标；更改目标不会立即删除现有记录，从下次保存新圈起应用。

「空间用量」显示圈数据估算、数据库占用与可复用空间，并按当前平均单圈大小估算目标容量。实际用量随圈长和样本数量变化，估算不含数据库索引与空闲页；删除后空闲页可被新记录复用，数据库文件不一定立即缩小。原始遥测录制使用独立的存储设置。圈列表按需显示，图表只读取所选圈，扩大保留数量不会预加载全部遥测样本。

在「弯道」页签选择分析圈，再选择或编辑区间。有兼容的固定参考时优先选中，否则默认「仅分析本圈」；无需参考圈即可查看区间耗时、最低速度、制动起点和恢复油门；也可从全部保留历史中选择兼容参考圈，比较两圈差异。旧记录缺少路线修订、保存的赛道或完整车辆信息时仍可查看单圈指标，界面会说明无法比较的原因；无法确认路线版本的区间标记按单圈保存。编辑时可在本圈走线预览上依次点击起点和终点，也可输入距离微调；走线支持缩放、平移和双击复位。样本不足的区间说明缺失原因，无法确认的输入事件显示为「—」；参考圈样本不足不会隐藏本圈已有指标。点击差异说明可返回速度曲线定位。编辑器和输入曲线按需展开或切换，关闭编辑器或切换页签不会清空未保存输入；切换赛道、参考对象或离开页面后应重新核对。

### 2.5 实验性漂移 HUD

漂移 HUD 默认关闭，根据本车 UDP 遥测推导侧滑角、控车余量和趋势提示。换挡建议侧重维持漂移、降低失控风险；漂移得分以游戏内显示为准。

启用漂移 HUD 时，圈速分析停止订阅且不写入新圈速；关闭后恢复原有设置。

### 2.6 地产环道与赛事

地产环道录入可随时暂存并恢复，地图预览会同步显示已采集的主路线和维修区数据。已保存赛道可分别修订起跑线、维修区入口、维修区路线、换胎区、出口和限速设置，不必重录整条赛道。普通赛道手动录入会先进入准备状态，并可在正式采集前取消。

地产赛事会结合参考路线弧长、实走距离和关键弯门生成切弯证据，并排除维修支路、倒车、瞬移和采样中断。维修区轨迹存在明显断点时会拒绝保存或启用，避免生成不可靠的计圈门。

连接 RaceServer 后可参加练习、排位和正赛，并接收旗语、处罚、调查、进站与发车状态。赛事 HUD 会提示高延迟、网络波动和重连状态；服务端开启断线计圈恢复后，客户端可在短时断线重连后补交本地完成的单圈。

「直连房间 · 实验」由房主创建或打开比赛项目，其他成员使用邀请代码和密码加入。直连需要双方的网络环境支持，须有可达的 TCP 或 UDP／QUIC 通路。客户端 `1.5.5` 配套房主组件 `0.6.0-r6`，加入者无需安装组件。直接连接失败时可交换回执，尝试 UDP 与反向 TCP；UDP／QUIC 要求双方使用支持 QUIC 的 Windows 11，反向 TCP 要求加入者有可入站地址。可选自动端口映射默认关闭。房主可打开本机 Web 总控管理赛事，并查看本次总控密码。组件按需下载并独立更新，支持离线导入、项目备份与恢复上一版。此功能同步 LazyForza 赛事数据，FH6 游戏车队在游戏内建立。详见[直连房间说明](ESTATE_PEER_ROOMS.md)。

碰撞调查结合短时冲击、双车接近轨迹、相对运动和可破坏物字段形成待审证据，只供总控复核，不自动判断责任。

### 2.7 语音比赛工程师

在地产赛事页启用语音工程师后，使用 Windows 已安装语音播报重要旗语、处罚、个人最快圈和进站预测。默认关闭，可调音量并立即静音；预测仍使用不确定性措辞。语音不可用不会影响比赛。

播报密度提供「精简／均衡／详细」三档：精简只自动播报旗语与处罚，均衡保留常规圈速与进站提醒，详细缩短圈速与进站变化的提醒间隔。展开「播报类别」可分别开关旗语、处罚、个人最快圈和进站建议；密度与类别自动保存，关闭类别会取消对应的待播和正在播放的消息。

「最近播报」默认折叠，显示最近 20 次播报的时间、类别、正文与状态，试听不计入。「重复上一条」使用当前音量，仅在最新一条完整播出、仍有效且所属类别开启时可用，不延长消息有效期。旗语变化、处罚修改／撤销／执行／移除、断线或赛事切换会使旧消息失效；真实赛事新消息优先。记录仅保留在内存中，重启或切换语音服务、音色后清空。

「语音服务…」浮窗提供「Windows 音色」选择，显示本机 SAPI 可用的中英文声音；默认跟随界面语言，选择英文音色时播报英文。音色保存后下次启动恢复；切换会停止旧声音并清理待播消息，保存的音色不可用时回退默认并提示。

原创无线电接通音结束后停顿 180 毫秒再播报，语音结束后停顿 220 毫秒再播放断开音。「自定义接通/断开音」支持分别导入 WAV、MP3、M4A 或 FLAC，每段最多 5 秒、10 MB，格式可用性取决于 Windows 解码器。导入后保存音频副本，移动原文件不影响播放；两种提示音均可单独恢复默认。

接通音和断开音可独立开关；关闭后跳过对应停顿，已导入音频继续保留。「试听」使用当前音色、音量和提示音开关。

「试听」按当前音量和提示音随机播放一条赛事示例，无需连接房间或启用自动播报；再次点击停止。静音、零音量和赛事切换会停止试听，真实赛事消息优先播放。

「语音服务…」还可选择 ElevenLabs、Azure Speech、腾讯云、阿里云智能语音交互、千问 AI 平台和 MiniMax，分别配置密钥、音色与模型。阿里云 NLS 使用项目 AppKey 与 RAM 凭据；千问使用平台 API Key 和 Qwen-TTS 音色，按两个独立服务配置。在线合成发送播报文本并使用相应账户额度，凭据由当前 Windows 用户加密保存。可开启服务故障时回退 Windows 本地语音。详见[语音服务配置](RACE_ENGINEER_SPEECH.md)。

### 2.8 窗口与设置

顶部品牌栏显示 Logo、版本号与更新名，支持拖动、双击最大化和边缘缩放。默认窗口为 1440×900 逻辑尺寸，按屏幕工作区调整；版本信息根据可用宽度同排、轮换或滚动，窗口失焦后暂停动画。

侧栏底部显示遥测状态和正在监听的 UDP 端口。「设置 → 常规 → 快速设置」可选择语音静音与音量、HUD 换挡提示、本车换挡推荐、HUD 整体不透明度、地产赛事底板不透明度、比赛自动录制和减少动态，默认显示静音与 HUD 换挡提示。已有自选项目保持原样，短窗口使用紧凑图标入口。HUD 换挡提示控制符号显示，本车换挡推荐控制当前车辆是否提供建议，两项独立保存。关闭比赛自动录制时会保存当前自动录制。

各快速设置的原控件旁都有图钉，点击固定到侧栏，再次点击移除；固定状态与常规设置的勾选列表同步。HUD 布局方案、连续实时 Delta 与 Delta 对比也可分别固定。固定或移除只改变入口，不改变开关状态或启动模块。

设置页修改后自动保存并应用，包括语言、HUD、录制与有效的遥测地址／端口。数据目录自动保存后提示重启，可自行选择重启时机。「地产赛事底板不透明度」可单独调淡面板背景；文字、旗语和状态标识由整体与组件不透明度控制。

### HUD 布局方案

在「设置 → HUD」顶部选择方案，或点击「新建方案」复制当前配置；名称右侧的图标用于重命名和删除。布局编辑器、HUD 设置和侧栏调整自动保存到当前方案，切换前保存尚未写入的修改。每份方案包含位置、缩放、部件显示与主题、透明度、动态和显示时序；模块启停、语音与遥测设置独立保存。

现有布局作为第一份方案保留，最多保存 32 份，名称最多 40 个字符。「重置当前方案」只恢复选中方案；至少保留一份方案。重启后恢复上次选择，配置备份包含全部方案。可在「设置 → 常规 → 快速设置」勾选「HUD 布局方案」，从侧栏列表直接切换，或通过「管理布局方案」返回 HUD 设置。

### 实时与分段 Delta

「当前比赛」顶部提供「连续实时 Delta」和「Delta 对比」，没有进行中的比赛时也可设置。连续实时 Delta 默认关闭，开启后按当前位置持续计算与参考圈的时间差，并保留通过分段及完成整圈时的短时 Delta。更快显示绿色负值，更慢显示黄色正值。

「Delta 对比」可选同赛道最佳、同性能等级最佳、同性能分最佳或同车辆最佳，默认同性能等级。四项都限定同一赛道、方向及兼容版本，使用真实有效完整圈；同车辆按车型筛选，可包含不同性能分。圈中修改时显示「下圈生效」，当前圈继续使用原参考圈。连续实时 Delta 开关即时生效，两个选项独立于 HUD 布局方案保存。

没有符合范围的参考圈或当前位置缺少参考采样时，实时值显示「—」。倒带或当前圈数据不连续后，下一圈重新开始比较。未收录路线在形成完整圈后也可作为后续圈的参考。侧栏中点击实时 Delta 图标切换开关，点击 Delta 对比图标直接选择四种范围；离线圈速分析仍使用其原有参考圈选择。

## 3. 数据、隐私与更新

### 3.1 本地数据目录

首次启动可选择以下目录：

- `%LOCALAPPDATA%\LazyForza`；
- `%LOCALAPPDATA%\LazyForza-Release`；
- 程序目录下的 `Data`；
- 任意自定义目录。

选择新目录后自动保存并提示重启，由用户选择重启时机；已有数据保留在原目录。

主要内容：

| 路径 | 内容 |
| --- | --- |
| `lazyforza.db` | 设置、车辆、赛道和圈速索引 |
| `Recordings` | 自动或手动遥测录制 |
| `Logs` | 运行日志 |
| `Backups` | 数据迁移备份 |
| `Diagnostics` | 用户主动生成的诊断资料 |
| `Updates` | 更新下载与临时文件 |
| `EstatePeer` | 可选房主组件、赛道项目及当前 Windows 用户加密的房间恢复状态 |

使用 `--data-dir` 可以指定独立目录：

```powershell
LazyForza.App.exe --data-dir "D:\LazyForza_Data"
```

### 3.2 隐私边界

- 默认不要求账号；
- 客户端个人数据保存在本机；
- 不读取游戏内存，不注入 DLL；
- 不伪造官方 UDP 未提供的赛道 ID、调校 ID、车辆尺寸或轮胎位置；
- 用户主动连接 RaceServer 或直连房间后，赛事所需的车手资料和遥测摘要才会发送到所选服务器或房主。

### 3.3 更新

正式安装版默认启动检查更新，正式便携版默认关闭，两者都可在设置中修改。正式版发现新版时先由用户确认，不强制安装；更新说明按当前界面语言显示中文或英文。程序优先使用 GitCode，失败时回退 GitHub：安装版下载并校验新版安装程序，完成系统安装信息和卸载清单升级；便携版校验 ZIP 的 SHA-256 与包内清单后原地更新，失败时恢复原版本。预览版使用独立初始化状态和 GitCode/GitHub 预发布更新通道，每次启动强制检查；可独立选择首选来源，未找到新版或检查失败时继续检查备用来源；发行列表按分页完整读取。发现更高预览版时自动下载、校验、替换并重启；正式版不参与预览通道，预览包不会自动转为正式版。检查或更新失败时可重试，也可继续使用当前版本并在设置中切换更新源。源码开发构建只提示新版，不自动下载或覆盖开发目录。正常升级不会改变已选择的数据目录或重复执行初始化。

## 4. RaceServer

RaceServer 是独立部署的赛事服务端，不是客户端运行所必需的组件。只进行日常驾驶和圈速分析时无需安装。

### 4.1 能力与规模

- 1–12 名车手，可单人发车；
- 最多 12 个只读 OB 席位，不占车手名额；
- 1–3 节练习与排位、正赛、五盏红灯和方格旗；
- 车队、维修区、进站规则、旗语、处罚、碰撞调查、路线收益切弯证据和可选断线计圈恢复；
- 阶段赛果归档，返回大厅后仍可回看，并支持 PNG/CSV 导出；
- 浏览器总控适配电脑宽屏和 Pad 触控；
- 原生 ASP.NET 与 Cloudflare Durable Objects 两种部署。

### 4.2 模拟换胎

地产赛事使用游戏内设置模拟换胎。按以下顺序操作：

1. 进入维修区；
2. 进入换胎区并将车辆停稳；
3. 暂停游戏，打开“设置 → 难度”；
4. 将“损坏与轮胎磨损”调为“外观”并保存；
5. 将“损坏与轮胎磨损”调回“拟真”，再次保存并返回游戏。

LazyForza 只核对车辆是否进入换胎区并满足停留条件，不读取暂停菜单，也无法确认游戏内设置是否完成。

### 4.3 选择部署方式

| 方式 | 适合场景 | 维护要求 |
| --- | --- | --- |
| 原生自托管 | 本地联机、VPS、长期固定服务器 | 自行维护进程、端口、TLS 和备份 |
| Cloudflare Durable Objects | 不想维护 VPS，接受 Cloudflare 平台 | 需要 Cloudflare 账号和 Workers 部署权限 |

两种实现使用同一协议和同一套 Web 总控功能。不要同时把两套服务指向同一个赛事房间。

### 4.4 原生服务端

从 [RaceServer Releases](https://github.com/Laz22y/LazyForza.RaceServer/releases/latest) 下载对应平台 ZIP：

- `win-x64`：Windows x64；
- `linux-x64` / `linux-arm64`：Linux；
- `osx-x64` / `osx-arm64`：macOS。

解压后启动：

```powershell
# Windows
./LazyForza.RaceServer.Web.exe init
./LazyForza.RaceServer.Web.exe
```

```bash
# Linux / macOS
chmod +x ./LazyForza.RaceServer.Web
./LazyForza.RaceServer.Web init
./LazyForza.RaceServer.Web
```

全新原生服务器必须先在服务器交互终端运行 `init`，设置房间密码、初始超级管理员密码和现有基础规则；密码不会回显。初始化完成后再启动服务，默认监听 `http://0.0.0.0:24876`。未初始化时正常启动会在监听端口前退出，浏览器和远程 API 不能完成原生首次设置。已有有效凭据的服务器升级后直接继续使用原配置。

公网部署应由 Caddy、Nginx 或同类反向代理终止 TLS。车手应连接 `wss://` 地址，不要把明文 `ws://` 暴露到互联网。

升级至 0.6.0 前备份整个服务端数据目录。0.5.0 的 `current-race.json` 仅为公开快照，应完成并归档当前赛事后移走该文件，再启动新版；已有 0.6.0 预览版恢复格式 v1 的文件可继续使用。新版保存成绩、处罚、阶段、恢复身份和事件去重记录，成功回执在持久保存后发送。进程重启后，进行中的赛事先以红旗暂停，管理员核对并发布全场绿旗后续赛。详细步骤见 [RaceServer 重启恢复说明](https://github.com/Laz22y/LazyForza.RaceServer#原生重启恢复)。

### 4.5 Cloudflare 部署

在服务端仓库使用“Deploy to Cloudflare”按钮，或在仓库根目录运行：

```powershell
./scripts/Deploy-Cloudflare.ps1
```

脚本要求 Node.js 20+、npm 和 PowerShell 7。部署完成后打开 Worker 域名完成首次设置，再上传 `.lfzestate` 赛道文件。

### 4.6 客户端连接

车手需要：

1. 服务端域名或 IP；
2. 房间密码；
3. 与房间匹配的地产赛道；
4. 显示名、主题色和可选车队。

OB 使用 OB 身份登录，只接收赛事快照，不上传遥测、不参与排名和处罚。

### 4.7 兼容性

RaceServer `0.6.0` 推荐搭配 LazyForza `1.5.5`，协议保持 v2。`1.5.3` 继续支持可靠圈回执、阶段归属和主动退出释放；更早的协议 v2 客户端保留相应主要赛事流程。断线计圈恢复需要客户端 `1.4.8` 或更高版本，并由服务端总控开启。直连房间使用配套房主组件，且需要双方网络环境支持。

## 5. 常见问题

### 客户端一直显示没有遥测

确认 FH6 已开启 Data Out，IP 为 `127.0.0.1`，端口为 `2299`。检查是否有其他程序占用端口，以及防火墙是否阻止本机 UDP。修改端口后，游戏和 LazyForza 必须一致。

### HUD 没有显示或挡住游戏界面

在设置中确认对应 HUD 已开启。进入布局编辑器检查显示器、位置、缩放和透明度；多显示器或分辨率变化后可恢复默认布局再调整。

### 赛道没有自动识别

先完成一段稳定驾驶，避免倒车、重置、暂停和大幅偏离路线。官方赛道目录只提供模板，用户自定义路线需要单独录入。无法可靠区分时，程序会要求人工确认。

### 自动录制停止

检查录制目录可用空间和容量上限。默认达到上限后停止，不自动删除。需要轮换时由用户明确开启，并确认重要录制已固定或备份。

### 无法连接 RaceServer

检查地址、房间密码和协议版本。公网环境需要 HTTPS/WSS，反向代理需转发 WebSocket Upgrade。网页可访问但客户端连接失败时，检查代理的 Upgrade 配置和 WebSocket 连接日志。

### 更新失败

保留提示中的错误信息和 `%LOCALAPPDATA%\LazyForza\Logs`。不要手动覆盖正在运行的程序；可以重新下载完整 ZIP，解压到新目录后启动。个人数据默认不在程序目录中。

## 6. 开发者指南

### 6.1 技术栈

- .NET 9；
- WPF 客户端与透明 Overlay；
- SQLite 本地存储；
- UDP 324 字节 FH6 Data Out；
- ASP.NET Core RaceServer；
- TypeScript + Cloudflare Workers / Durable Objects。

### 6.2 客户端构建

需要 Windows 10/11 x64、.NET SDK 9 和 PowerShell 7：

```powershell
git clone https://github.com/Laz22y/LazyForza.git
cd LazyForza
dotnet restore LazyForza.sln --configfile NuGet.Config
./scripts/Test-Client.ps1
dotnet run --project src/LazyForza.App/LazyForza.App.csproj --no-build --no-restore -c Debug
```

`Test-Client.ps1` 默认构建并执行快速检查；可使用 `-Project` 和 `-Filter` 缩小到相关测试。`-Suite Full -Configuration Release` 包含全赛道穷举与真实网络超时测试，用于发行前和涉及这些行为的改动。每次运行的日志、TRX 与耗时摘要保存在 `artifacts/tests/`。

开发和 QA 可使用隔离数据目录：

```powershell
dotnet run --project src/LazyForza.App/LazyForza.App.csproj -- --data-dir ".\.dev-data"
dotnet run --project src/LazyForza.App/LazyForza.App.csproj -- --demo
dotnet run --project src/LazyForza.App/LazyForza.App.csproj -- --replay "C:\path\session.lfztelemetry"
```

### 6.3 客户端项目结构

| 项目 | 职责 |
| --- | --- |
| `LazyForza.Telemetry` | UDP 接收、解析和遥测帧 |
| `LazyForza.Domain` | 领域模型与公共类型 |
| `LazyForza.Analysis` | 圈速、路线、分段与驾驶分析 |
| `LazyForza.Storage` | SQLite、录制、备份与数据目录 |
| `LazyForza.Modules.*` | 仪表盘、圈速和地产赛事模块 |
| `LazyForza.Overlay` | 透明 HUD、布局与格式化 |
| `LazyForza.Update` | 更新检查、校验与替换 |
| `LazyForza.App` | WPF 主程序和模块装配 |

主数据流：

```text
FH6 UDP → Telemetry → Domain Frame → Modules → Analysis / Storage → App / Overlay
```

### 6.4 RaceServer 构建

```powershell
git clone https://github.com/Laz22y/LazyForza.RaceServer.git
cd LazyForza.RaceServer
dotnet restore LazyForza.RaceServer.sln
dotnet build LazyForza.RaceServer.sln -c Release --no-restore
dotnet test LazyForza.RaceServer.sln -c Release --no-build --no-restore

cd cloudflare
npm ci
npm run check
npm test
```

原生端与 Cloudflare 端共享协议语义，但各自维护状态实现。任何赛事协议、总控接口或 Web 功能变更都必须同步修改并补齐双端测试。

### 6.5 协议字段边界

FH6 官方 Data Out 固定为 324 字节。可以直接获得位置、速度、姿态、输入、动力、悬挂和轮胎状态等字段，但不提供：

- 官方赛道 ID 和赛事 ID；
- 对手车辆遥测；
- 调校 ID、宽体或精确车辆几何。

开发时以官方字段定义为准。推导数据必须与官方字段明确区分。
