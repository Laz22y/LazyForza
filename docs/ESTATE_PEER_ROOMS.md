# 地产赛事直连房间（实验）

在「地产赛事」选择「直连房间 · 实验」。房主在本机运行比赛权威核心，其他成员直接连接房主；比赛不使用房间目录、STUN、TURN、公共 IP 查询或中继服务。此功能同步 LazyForza 的赛事数据，FH6 游戏车队仍需在游戏内建立。

## 创建与加入

- **加入房间**：粘贴完整邀请代码，输入密码和显示名，可选 OB 身份。客户端验证房主证书指纹后读取赛道信息；缺少赛道时按既有确认流程下载并校验赛道包。加入者无需安装房主组件。
- **新建与打开**：首次安装房主组件。「新建项目」创建独立比赛；「打开项目」继续保存的比赛，默认选中最近打开的项目。只有房主启动成功才保存新项目，失败重试不会增加空项目。填写房间名与 6–128 位密码，圈数和网络选项收在「比赛与网络设置」中，默认 TCP／UDP 端口为 24878。
- **分享邀请**：复制完整 `LFZP2-…` 代码，另行分享密码。紧凑格式保留完整房主公钥指纹，新客户端仍可读取 `LFZP1-…`。代码自带地址，短房间编号仅用于核对。通过可信渠道分享代码。
- **通过回执连接**：TCP 不可达且双方支持 QUIC 时，加入窗口显示 `LFZR1-…` 回执。玩家复制给房主，房主在「通过回执连接」中添加，再通知玩家点击「继续连接」。回执十分钟内有效，仅适用于生成时的房间和邀请代次。双方主动发送 UDP 探测，经 QUIC 建立加密通路，赛道下载与赛事消息均经过该通路。
- **房主管理**：「打开 Web 总控」进入与原生服务端相同的页面，管理阶段、旗语、处罚、调查、车手、规则、项目和赛果。直连窗口为普通非模态窗口，可同时操作主界面；常用控制收在折叠区域内。
- **刷新与重连**：邀请有效期为一天。刷新或恢复房间会更新邀请代次；旧代码不能用于新加入，已认证成员保留恢复身份。地址变化后需要重新分享新代码。
- **关闭与恢复**：关闭管理窗口保持房间运行；关闭房间或退出应用停止组件。再次创建时选择原房间项目、输入原密码；中断的阶段需房主通过绿旗确认后继续。恢复使用项目保存的原赛道包。

Web 总控仅监听房主的 `127.0.0.1` 地址，客户端通过短时、一次性入口建立浏览器会话；玩家连接端口不开放管理接口。房主是本场比赛的权威节点，不支持自动迁移房主。

## 可选组件与存储

房主组件单独安装，不进入默认客户端包。窗口使用内嵌清单显示下载与安装大小。组件包含原生服务端的固定版本赛事核心与 Web 总控，自带运行时，无需额外安装 ASP.NET。

组件通过独立的 [GitHub 分发仓库](https://github.com/Laz22y/LazyForza.Components/releases)与 [GitCode 分发仓库](https://gitcode.com/Laz22y/LazyForza.Components/releases)下载。下载服务只负责获取程序，不参与建房、寻址或比赛；组件安装后可离线使用。加入房间无需下载组件。

在「创建房间 → 房主组件」展开区中选择「检查组件更新」，即可独立更新房主功能，无需等待客户端发布。组件编号采用「服务端版本-r组件修订」，例如 `0.6.0-r1`：升级服务端时跟随其版本，仅修改房主适配时递增 `r2`、`r3`。发布清单同时记录实际封装的服务端提交。组件更新沿用客户端的 GitCode／GitHub 来源偏好，失败时尝试另一来源；正式客户端不接受预览组件。

更新必须通过客户端内置公钥的 ECDSA 签名校验，以及 ZIP 和每个文件的 SHA-256 校验。客户端只提供版本范围、本机控制协议、赛事协议和项目格式均兼容的更新。需先关闭房间才能安装；新版完整安装并备份项目后才切换版本，中断或备份失败保留原版本。已有可用旧版本时可选择「恢复上一版本」，回退程序不会覆盖更新后的比赛结果。

离线首次安装客户端内嵌版本时，可直接导入配套 ZIP。离线升级到其他版本时，将该版 ZIP 与 `estate-peer-component.signed.json` 放在同一个文件夹，再选择「导入离线包」。首次接受更新需要有效且未过期的签名清单；已经验证并保存的版本可继续离线运行或修复。

组件位于用户数据目录的 `EstatePeer/Components/<SHA-256>`，当前版本选择保存在 `component-selection.json`；项目位于 `EstatePeer/Rooms/<项目 ID>`，更新和回退前的项目备份位于 `EstatePeer/Backups/Components`。项目包含赛道包、项目描述及 Windows 当前用户加密的房间身份／比赛状态；`Control` 子目录保存 Web 总控的配置、素材和赛事项目。卸载组件保留项目；移到另一 Windows 用户或电脑的加密身份不能直接解密。

## 网络条件

| 环境 | 使用方式 |
| --- | --- |
| 同一局域网 | 使用邀请中的局域网候选；静态无网关网络可手动填写房主网卡 IP |
| 双方有可达 IPv6 | 先尝试 TCP；入站受状态过滤时可交换回执，尝试双向 UDP，实际能否连接取决于网络策略 |
| 公网 IPv4 在房主电脑 | 填写该地址，并允许本应用端口的入站连接 |
| 公网 IPv4 在路由器 | 手动映射 TCP；使用 UDP 时也需将 UDP 映射到同一端口，填写外部 IP 与端口 |
| 双重 NAT | 每一层都需要有效的映射／路由路径 |
| CGNAT、DS-Lite | 检查是否有可达 IPv6；只有不可映射的共享 IPv4 时无法作为可入站房主 |
| 访客网络、AP 隔离、企业策略、强制代理 | 网络可能阻止直连，需要调整网络或更换房主；软件不绕过策略 |
| 多网卡、VPN、重叠网段 | 可以补充指定地址；实际路径依赖系统路由，需核对网络配置 |

TCP 直连保留 Windows 10／11 支持；UDP／QUIC 通路要求双方使用支持 QUIC 的 Windows 11 环境。最多尝试代码内 8 个地址，不扫描网段，不自动修改防火墙或申请路由器映射。回执包含网卡地址，不能自动得知 CGNAT 分配的外部地址与端口。双向 UDP 探测能利用部分网络已有的状态过滤行为，不能保证所有网络环境都可达。

监听成功只表示本机已就绪；异地完整连接必须由两台兼容 Windows 客户端验证。以下命令仅用于 TCP 路径诊断，不能验证 QUIC 回执加入。

## 连接路径检查

使用一台运行房主组件的 Windows 设备和另一台独立诊断设备，先检查 TCP／HTTPS 路径。以下检查不验证房间认证、赛事同步或 FH6 多机行为。

### 准备房主

1. 在「地产赛事 → 直连房间 · 实验 → 创建房间」安装配套组件，选择已有赛道并创建房间。
2. 保持房间运行，记下实际监听端口，默认 `24878`。使用 `ipconfig` 查看可用网卡地址。
3. 检查目标端口的监听、路由和防火墙规则；不要关闭整个防火墙，也不需向其他设备开放 FH6 遥测端口 `2299`。

### 检查 TCP 与 HTTPS

在诊断设备的 PowerShell 中执行。下方 `192.0.2.20` 和 `2001:db8::20` 均为文档保留地址，必须替换为房主的实际目标地址：

```powershell
Test-NetConnection -ComputerName '192.0.2.20' -Port 24878
curl.exe --noproxy '*' -4 -k -sS --connect-timeout 5 --max-time 10 -o NUL -w 'HTTP %{http_code}\n' 'https://192.0.2.20:24878/peer/identity'

Test-NetConnection -ComputerName '2001:db8::20' -Port 24878
curl.exe --noproxy '*' -6 -k -sS --connect-timeout 5 --max-time 10 -o NUL -w 'HTTP %{http_code}\n' 'https://[2001:db8::20]:24878/peer/identity'
```

`TcpTestSucceeded: True` 表示 TCP 建连成功。无凭据请求当前通常返回 `HTTP 404`，表明已收到 HTTPS 响应。`-k` 仅用于无密码的路径诊断，不能确认房主身份，也不能用于提交密码；正式客户端仍校验证书指纹。关闭房间后对应端口应不再可达，重新创建后恢复，以排除测到了其他服务。

### 分别检查不同路径

先完成局域网检查，再使用独立网络检查跨网路径。确认诊断设备没有经其他网卡或 VPN 回到原局域网；仅更换同一路由器的无线频段不能证明跨网可达。

| 路径 | 准备与检查 |
| --- | --- |
| 公网 IPv4 | 确认房主或网关拥有可入站地址；需要映射时，将外部 TCP 端口指向房主监听端口 |
| 全局 IPv6 | 双方具备可用 IPv6 路由，目标为房主网卡全局地址，且相关入站规则允许通信 |
| 共享 IPv4／多层 NAT | 私有地址或 `100.64.0.0/10` 不能直接作为公网目标；每一层都需要有效的映射或路由路径 |

记录地址族、目标端口、TCP 结果和 HTTP 状态。连接被拒绝时检查监听与映射；超时只说明未收到及时响应，不能单独判断原因。不要用 `ping` 代替 TCP 检查。完整的邀请加入、赛道同步、比赛和断线恢复仍需两个兼容 Windows 客户端分别验证。

## 开发与验证

- 架构与网络矩阵：[ADR-0002](adr/ADR-0002-estate-peer-hosting.md)。
- 权威引擎固定依赖：[离线包说明](../vendor/estate-peer-engine/README.md)。
- 本机测试覆盖认证、容量、邀请兼容与刷新、项目启动事务、原生总控、UDP 内的赛道传输和赛事连接、可靠事件确认、模块接线及恢复；组件测试覆盖签名、兼容版本、独立修订、来源回退、项目备份、回退和中断重试。WPF 离屏测试覆盖中英文及 520／680 宽窗口。跨网络双向 UDP 路径已有小范围检查结果，完整 QUIC 加入、长期比赛和真实 FH6 多机仍待验证。

### 发布独立组件

所有构建和签名在本机完成，不依赖 CI。服务端变更先在 RaceServer 两套实现验证并提交，再运行 `Sync-EstatePeerEngine.ps1` 和 `Sync-EstatePeerControl.ps1`，同步更新中央包版本。两份 provenance 的服务端版本与提交必须一致；打包脚本从中读取版本，拒绝手动指定不匹配的版本。

```powershell
pwsh scripts/New-EstatePeerComponent.ps1 -Revision 1
pwsh scripts/New-EstatePeerUpdateManifest.ps1 -CatalogPath '<输出目录>/estate-peer-component.json' `
  -MinimumClientVersion '1.5.4-alpha-1' -MaximumClientVersionExclusive '1.6.0' `
  -Channel preview -Sequence 2026092101
```

`Sequence` 每次发布递增；客户端范围与协议／项目格式要以实际兼容检查为准。清单默认六个月有效，发布前可以指定 `ExpiresAt`。将原始 ZIP、对应 `.sha256` 和 `estate-peer-component.signed.json` 上传到双平台分发仓库同名 Release，例如 `estate-peer-host-v0.6.0-r1`；预览组件标为预发布。不能重新压缩已签名的包。客户端首次配置下载时，将生成的 `estate-peer-component.downloads.json` 作为内嵌清单；后续兼容组件更新不需要重新发行客户端。

签名使用当前 Windows 用户 CNG 密钥 `LazyForza.ComponentSigning.v1`，由 `Initialize-EstatePeerSigningKey.ps1` 初始化；只把公钥提交到源码，私钥不可导出且不上传。后续发布需在拥有该密钥的用户环境中签名。密钥丢失或更换时，需要通过客户端更新分发新的信任公钥，不能直接替换分发仓库中的签名。
